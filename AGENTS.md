# AGENTS.md — How agents build this project

## Project
`/Users/ym/app/s3vector_client` — pure static SPA web client for **AWS S3 Vectors** (all 16 API actions, see `docs/PLAN.md`). Attu (zilliztech/attu) is the UX reference; AWS SDK for JS v3 (`@aws-sdk/client-s3vectors`) is the API layer, called directly from the browser with user-supplied credentials.

## Hard rules
1. **No backend.** The build artifact is a static page. Runtime config comes from the user's Settings (region, AK/SK, optional session token, optional endpoint override), persisted in localStorage unless "session-only" is chosen. Never bake credentials into the build.
2. **TypeScript strict.** No `any` in the API layer; type SDK responses precisely.
3. **Every feature module ships unit tests.** Mock the SDK at the service-layer boundary (`vi.mock`); test UI states: loading, empty, error, data. `npm test`, `npm run lint`, `npm run build` must all pass before a round is considered done.
4. **Design system compliance.** UI follows `DESIGN.md` (repo root) generated by the design agent from `awesome-design-md/design-md/`. Do not invent ad-hoc colors/spacing; use the design tokens.
5. **UX parity with Attu:** left sidebar nav (Dashboard, Vector Buckets, Settings, + context drill-downs), tables with search/pagination, JSON viewers for metadata/policies, confirm dialogs for all destructive ops, friendly error banners with AWS error names.
6. **Commits:** only the Review/Commit agent (S5) commits, one commit per reviewed round, conventional-commit messages (`feat(scope): ...`).
7. `awesome-design-md/` is vendored reference only — keep it gitignored, never import from it.

## Commands
- dev: `npm run dev` (Vite, port 5173)
- test: `npm test` / `npm run test:run` (Vitest)
- lint: `npm run lint` (ESLint + Prettier)
- build: `npm run build` (tsc + vite build)
